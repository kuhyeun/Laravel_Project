 3. UI Kit 갤러리 + 공용 컴포넌트
================================================================================

[내용]

 - 갤러리는 같은 컴포넌트를 props만 바꿔 전시 + 사용 코드 복사 버튼

 4. 메뉴/메뉴권한 관리(MenuManage) 페이지
================================================================================
[목적] 메뉴 신규등록/수정/삭제 + 레벨별 권한(노출/등록·수정/삭제) 관리.
       사용자 메뉴 + 관리자 메뉴 둘 다.

[스키마 변경 - 마이그레이션(신규)]
 - packages/mes-core/database/migrations/2026_08_24_000001_add_is_admin_to_system_menu_table.php
     system_menu.is_admin (Y/N) - 관리자 메뉴 여부 (기존 코드와 불일치 해소)
 - packages/mes-core/database/migrations/2026_08_24_000002_add_permissions_to_system_menu_option_table.php
     system_menu_option.can_read / can_write / can_delete (Y/N)
     = 노출(읽기) / 등록·수정 / 삭제  (account_menu_permission과 동일 구성)

[변경 파일]
 - packages/mes-core/src/Menu/Models/Menu.php (fillable, validateMenuData 보강)
 - packages/mes-core/src/Menu/Models/MenuOption.php (fillable + 권한 기본값)
 - packages/mes-core/src/Menu/Controllers/MenuController.php
     update/delete 구현, saveMenuOptions(레벨 rwx+정렬) 추가, list() 추가,
     검증 실패(422) 정상 응답 처리
 - packages/mes-core/routes/menu.php (list, saveMenuOptions 라우트)
 - packages/mes-core/src/Menu/Services/MenuPermissionService.php
     레벨 기본 권한을 menu_option의 rwx 실제값으로 읽도록 변경
 - packages/mes-core/resources/js/Pages/Basic/MenuManage.vue (전체 구현)
     사용자/관리자 탭, 메뉴 트리, 상세폼(신규/수정), 레벨별 권한 그리드

[is_admin 분류 및 사이드바 그룹 분리]
 - 규칙: menu_level <= 1 (0 시스템, 1 관리자) 인 메뉴 = 관리자 메뉴
 - 시더(MenuSeeder.php)가 is_admin 자동 설정 (재현 가능) + 기존 데이터 재시드로 백필
 - 사이드바에서 관리자(시스템) 메뉴를 별도 "시스템" 그룹으로 분리
   * MenuPermissionService: is_admin 기준 트리 2개(menus / adminMenus)로 분리,
     부모가 다른 그룹이면 최상위로 올려 고아 메뉴 유지
   * HandleInertiaRequests: adminMenu prop 공유
   * AppLayout.vue / LeftMenu.vue: 시스템 그룹 렌더

 5. 403 권한 에러 페이지
================================================================================
[목적] "Permission Denied." 텍스트 대신 꾸며진 에러 화면.

[변경/새 파일]
 - packages/mes-core/src/Auth/Middleware/AdminAuth.php (response→abort(403))
 - packages/mes-core/src/Auth/Middleware/LevelAuth.php (response→abort(403))

 - packages/mes-core/resources/js/Pages/Error.vue (신규 - status별 메시지)
 - packages/mes-core/resources/js/Layouts/BlankLayout.vue (신규 - 프레임 없는 레이아웃)

[내용]
 - 미들웨어가 abort(403)으로 던져 렌더 파이프라인 진입
 - Error 페이지는 BlankLayout 사용 → Top/좌측메뉴/Bottom 프레임 없이 표시
 - 레이아웃 선택으로 "프레임 유무"를 페이지별로 제어
   (AppLayout=프레임 O, BlankLayout=프레임 X)


================================================================================
 6. 제네릭 페이지 라우팅 전면 전환 (핵심)  ★★★
================================================================================
[목적] 메뉴 추가 시 routes에 일일이 라우트/컨트롤러를 작성하는 불편 제거.
       => 페이지를 DB(url_path/page_component) 기반으로 렌더.

[결정사항]
 - 전면 전환 (하이브리드 아님, props 페이지는 API로 이전)
 - URL 방식: 저장된 url_path 컬럼
 - 화이트리스트: DB값 신뢰 + 저장 검증 + 렌더 시 파일 존재 확인
 - 권한: 레벨 제약 강제 (menu_option 레벨 기준)

[Phase 1] 스키마·모델·시더
 - 마이그레이션(신규):
   packages/mes-core/database/migrations/2026_08_26_000001_add_page_routing_to_system_menu_table.php
     system_menu.url_path (unique) + page_component
 - Menu.php: fillable + 검증(url_path 형식/unique, page_component 경로탈출 차단)
 - src/database/seeders/Menu/MenuSeeder.php:
     url_path는 menu_route_name에서 유도, page_component는 매핑 테이블로 백필
     (실제 페이지 11개 백필, 업무 placeholder 메뉴는 null)

[Phase 2] 제네릭 렌더러
 - packages/mes-core/src/Page/Controllers/PageController.php (신규)
     url_path 조회 → 로그인 → menu.read Gate → 컴포넌트 존재 확인 → Inertia::render
     (실패 시 404/403 → Error 페이지)
 - packages/mes-core/src/CoreServiceProvider.php
     Route::fallback을 맨 마지막에 등록

[Phase 3] 데이터 API (props → fetch)
 - MenuController@list (GET /menu/list) / BasicController@systemConfigData
   (GET /basic/systemConfig/data)
 - MenuManage.vue / SystemConfig.vue: props 제거 → onMounted에서 axios fetch,
   CRUD 후 재조회

[Phase 4] 사이드바 링크 전환
 - MenuPermissionService: payload에 url_path 추가
 - MenuItem.vue: route(menu_route_name) → url_path 기반 (ziggy 제거)

[Phase 4.5] 레벨 제약 강제
 - MenuPermissionService::can(): bypass 단락 제거
   => payload(레벨별 필터링된 메뉴)에 없는 메뉴는 거부.
      레벨 ≤1도 자기 payload 메뉴만 접근 (레벨 0 전용 페이지를 레벨 1이 못 봄)
 - config/menus.php: member/memberAuth/preferences의 menu_level 10 → 1
   (관리자 전용 유지), 시더가 범위 밖 옵션(레벨10) 제거하도록 보완 후 재시드

[Phase 5] 기존 라우트/컨트롤러 정리
 - packages/mes-core/routes/basic.php: 페이지 GET 제거, 데이터/도구 엔드포인트만
 - BasicController.php: 렌더 메서드 제거 (systemConfigData, uiKit만 유지)
 - SampleController.php: 차트/api 렌더 메서드 제거 (apiGet/apiPost 유지)

[결과 - 새 페이지 추가 방법]
  1) 메뉴 관리 UI에서 메뉴 등록 (url_path + page_component 지정)
  2) 해당 Vue 컴포넌트 파일 생성
  => 라우트/컨트롤러 작성 불필요.
     데이터가 필요하면 별도 JSON 웹 엔드포인트를 만들어 페이지가 fetch.

================================================================================
 주의사항 / 후속 작업
================================================================================
 1) [DB] 아래 마이그레이션 3개는 이미 실행 완료. 다른 환경/신규 설치 시:
      docker exec laravel_php php artisan migrate
      docker exec laravel_php php artisan db:seed --class="Database\Seeders\Menu\MenuSeeder"

 2) [Vite] 새로 추가한 Vue "페이지" 파일(UiKit, MenuManage, Error 등)은
    dev 서버가 실행 중일 때 최초 인식을 위해 재시작이 필요할 수 있음.
      cd src && npm run dev

 3) [uiKit 라우트] basic.php에서 /basic/uiKit 라우트를 제거한 경우,
    UI Kit은 메뉴에 등록돼 있지 않아 접근 시 404가 남.
    - 계속 쓰려면: 메뉴에 등록(url_path=/basic/uiKit, page_component=Basic/UiKit) 하거나
      basic.php에 명시적 라우트를 다시 두어야 함.
    - BasicController@uiKit 메서드도 라우트가 없으면 사용되지 않음(정리 대상).

 4) [권한 캐시] 메뉴/권한 변경은 per-user 캐시(TTL 60초)라 최대 60초 후 반영.
    즉시 반영하려면: docker exec laravel_php php artisan cache:clear

 5) [샘플 데이터] SystemConfig의 CONFIG_DATA는 아직 데모용 샘플값.
    실제 저장/로드가 필요하면 별도 저장소(테이블/설정) 설계 필요.

 6) [git] 변경 범위가 크므로 커밋 전 검토 권장. (이 파일 작업정리.txt는 커밋 대상에서
    제외하거나 docs로 옮겨도 됨)
